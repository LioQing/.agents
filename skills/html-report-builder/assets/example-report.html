01 · Readout

Executive summary

The system absorbed more demand with less latency. A cache-policy rollout reduced p95 latency by 19% while request volume increased 12%. The gain appears durable across every observed region.

Risk is concentrated, not systemic. Checkout produced 61% of failed requests despite carrying only 18% of traffic. The failure mode is an upstream payment timeout with a known mitigation.

info

Recommendation: ship bounded retries and a circuit breaker for the payment adapter before expanding traffic allocation beyond 60%.

05 · SLO

Error-budget accounting

For a 99.9% monthly availability objective, the allowed bad-request ratio is \(1-SLO\). Budget consumption compares observed failures with that allowance.

\[\text{Budget used}=\frac{\text{failed requests}}{\text{total requests}\times(1-SLO)}\times100\%\]

At the current burn rate, the service has 57% of its monthly budget remaining. Checkout remediation has the highest leverage because its failures dominate the numerator.

06 · Implementation

Bound retries by time and count

The retry must fit inside the request deadline and preserve the payment idempotency key.

Python
async def charge_with_retry(payment, *, deadline_ms=800):
    for attempt in range(2):
        try:
            return await gateway.charge(
                payment,
                idempotency_key=payment.order_id,
                timeout_ms=deadline_ms // 2,
            )
        except GatewayTimeout:
            if attempt == 1:
                raise
